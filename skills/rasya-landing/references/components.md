# Components

Choose section patterns that match the commercial job.

## Page Patterns

```text
Conversion Path: hero -> proof -> problem -> mechanism -> offer -> pricing -> FAQ -> CTA
Product Story: hero -> object reveal -> benefits -> material/specs -> variants -> buy
Technical Proof: hero -> workflow -> feature widgets -> integrations -> security/proof -> pricing
Service Trust: hero -> proof -> services -> process -> outcomes -> testimonials -> contact
Editorial Brand: masthead -> manifesto -> selected proof -> product/work index -> CTA
```

## Hero Patterns

- Asymmetric split with product or interface breaking the grid
- Editorial masthead with oversized type and a product strip
- Device/interface hero with one believable, functional mockup
- Product object hero with material-focused image/video
- Centered launch hero only when the page is announcement-like or the style justifies it

## Proof Patterns

- Stat row in open space, not always cards
- Before/after comparison
- Single strong pull quote
- Case study slice with real context
- Integration map only when integrations are real
- Logo wall only with real logos or clearly fictional placeholders

## Feature Patterns

- One hero feature plus supporting details
- Sticky stack
- Paired feature with mini UI widget
- Alternating deep dive, capped at two consecutive uses
- Bento grid only when cell sizes reflect information hierarchy

## CTA Patterns

- Offer-specific CTA band
- Product object CTA
- Pricing CTA
- Consultation CTA
- Waitlist/launch CTA

CTA sections should not all look the same. Repetition of action is fine; repetition of layout is lazy.
